Project · optics simulation site

From ray-tracing scripts to a PhET-style site

The plan for turning your Python ray-tracing work (thin/thick lenses, mirrors) into an interactive, multi-simulation website — ported to simple client-side math, no backend.

JavaScript / TypeScript Canvas rendering No backend Static hosting VS Code + ESLint + Prettier
1

Lock in the tech decisions

In progress

Pure client-side JavaScript, no backend, no Pyodide — your math is simple enough to hand-port. Still open: JavaScript vs. TypeScript, and whether to add a bundler like Vite or stay with plain files.

So far Editor set up in VS Code — ESLint installed, Prettier and Live Server recommended, and the built-in JavaScript debugger confirmed working.
2

Port the core ray-tracing math

In progress

Translate the model layer — surface intersection, Snell's law refraction, mirror reflection, thin- and thick-lens handling — into a standalone JS module with no UI code in it. Spot-check outputs against the Python scripts before building anything on top.

So far First piece written: a point-source ray generator (getRayAngles) that fans rays evenly across a given angular field — the seed of the model layer.
3

Build shared interactive building blocks

In progress

The reusable pieces every sim will need: a physical-units-to-pixels coordinate system, draggable-object handling (mouse and touch), a ray/line renderer, and basic UI controls (sliders, reset button).

So far Established the file pattern — index.html for structure, script.js for logic — and a working canvas renderer for a point source and its ray fan. Coordinate scaling and dragging are still ahead.
4

Build one simulation end-to-end

Not started

Take the thin-lens sim all the way to fully working and polished: draggable object and lens, real-time ray redraw, adjustable focal length, labeled focal points. This establishes the pattern the other three sims will follow.

5

Replicate the pattern for the rest

Not started

Mirrors (plane / concave / convex), refraction & Snell's law, and prism dispersion — each gets its own page, reusing the Stage 3 building blocks and Stage 2 math, adapted to its own geometry.

6

Build the hub / landing page

Not started

A simple index page listing all four simulations — like PhET's simulation index — linking out to each one and tying the project together as one site.

7

Polish pass

Not started

Responsive layout, touch-drag support, labels and units, wavelength-based ray coloring where relevant, a reset-to-default button, and basic accessibility considerations.

8

Validate and test

Not started

Cross-browser check, a full pass comparing outputs against the original Python scripts across a range of inputs, and informal use-testing — drag things around and see what feels off.

9

Deploy

Not started

Push the static files to a free host — GitHub Pages, Netlify, Vercel, or Cloudflare Pages all work — and wire up auto-deploy on push.

+

Optional extras, later

Not started

Shareable links that encode sim state in the URL, diagram export/screenshot, more advanced optical setups (multi-lens systems, aberrations), or usage analytics.

Nine stages, roughly in order — Stage 2 (the math) is worth finishing in isolation before much UI gets built on top of it, so bugs in the physics and bugs in the rendering never have to be untangled at the same time.
